# Промпт № 6 — синхронизировать инструкцию и выполнить следующий шаг по Acer

Это рабочая команда для текущей сессии Hermes. Не делай длинный отчёт-план. Выполняй по шагам, фиксируя фактический результат.

## Шаг 1. Синхронизация инструкции

Прочитай и выполни:
https://github.com/convergentaru/paperclip/blob/docs/night-shift-agent-foreman-plan/docs/prompts/robot-factory/05-sync-runbook-to-jetbrains-obsidian.md

Каноническая инструкция:
https://github.com/convergentaru/hermes-agent-self-evolution/blob/feat/local-verified-learning-loop/docs/runbooks/ACER-RESCUE-USB-AND-SSH-RU.md

Перенеси runbook в локальный JetBrains-проект `~/projects/acer-rescue-usb`, Obsidian vault и существующий индекс/GBrain по фактическим путям. Не говори «готово», пока не сравнил SHA-256 копий и не проверил индексы. Если GBrain API/CLI не удаётся подтвердить, не угадывай; обнови существующий Markdown-индекс и отметь GBrain ingestion как непроверенный.

## Шаг 2. Не записывать USB повторно

Владелец сообщил, что ISO уже записан на физическую USB-флешку, которая предназначена для удалённого Acer. Отсутствие USB в `lsblk` на домашнем Ubuntu ожидаемо, если носитель находится в другом городе.

Поэтому:
- не требуй подключить флешку к домашнему компьютеру;
- не запускай `dd`, не форматируй накопитель и не пересобирай ISO;
- повторная запись допустима только если обнаружен конкретный дефект существующего образа/носителя и владелец отдельно подтвердил целевое устройство.

## Шаг 3. Выполнить локальный preflight самому

Выполни безопасные команды на домашнем Ubuntu:
- `tailscale status`
- `tailscale ip -4`
- `tailscale netcheck`
- `cd ~/projects/acer-rescue-usb && git status --short && git log -1 --oneline`
- найти существующие ISO и их SHA-256;
- прочитать актуальные конфиги/скрипты проекта, чтобы достоверно установить ожидаемое имя rescue-узла, метод регистрации Tailscale, имя SSH-пользователя, способ запуска SSH/Tailscale и ожидаемые логи.

Не угадывай hostname, IP, пользователя, порт, key или команды. Не меняй глобальный Tailscale/SSH/firewall/Hermes config.

## Шаг 4. Попытаться подключиться

Сначала снова проверить `tailscale status`. Если конкретный rescue-узел присутствует, проверить его через `tailscale ping` и затем через подтверждённую конфигурацию SSH. После успешного входа выполнить только read-only диагностику: `hostname`, `uptime`, `uname -a`, сетевые адреса/маршруты, Tailscale status, `lsblk`, `findmnt`, `swapon --show`.

Не ремонтировать Windows, не изменять EFI/таблицу разделов и не монтировать внутренний диск read-write.

## Шаг 5. Если удалённый узел ещё не появился

Сначала заверши все доступные локальные проверки. Затем сформулируй человеку на месте только конкретное действие:

1. вставить уже записанную rescue-флешку в Acer;
2. включить компьютер и нажимать F12;
3. выбрать USB/UEFI загрузку;
4. не запускать установку ОС и не изменять внутренний диск;
5. если загрузка не удалась — прислать фото текущего экрана.

Не проси его подключать USB к домашнему компьютеру и не предлагай повторную запись. После появления rescue-узла в Tailscale продолжи подключение/диагностику, используя уже прочитанный runbook.

## Завершение

Отчитайся коротко:
- локальная синхронизация: пути JetBrains/Obsidian, индексы, SHA-256 и push/commit;
- домашний Tailscale: реальный status/IP/netcheck;
- rescue-узел: найден/не найден;
- Tailscale ping и SSH: фактический результат/exit code;
- если блокер — одно конкретное действие, которое требуется от человека у Acer;
- следующий практический шаг.

Не объявляй работу законченной из-за нового файла или LESSONS.md. Практический критерий — rescue-узел обнаружен и удалённый доступ работает, либо точно установлено, какое физическое действие ещё нужно.
